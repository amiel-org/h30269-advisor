# 沪深300决策台：业务、代码与刷新问题审计

审计日期：2026-10-15。代码版本 v2.4，原始基线 Git `5ca0968`。

结论：发现并修复多处实际缺陷。此前“测试全部通过”没有覆盖浏览器脚本解析，也没有保证页面提示、命令行和回测采用相同交易口径。修复后可以作为规则研究和人工决策参考，不能声称已有经过核实的实盘获胜记录。

## 已证实的问题及修复

| 问题 | 影响 | 修复 |
|---|---|---|
| 前端 `const el = #freshBanner` 语法错误 | 整个模块无法执行，页面一直显示读取中，根本未发起数据加载 | 修正选择器；构建前校验全部顶层 JS 语法 |
| 页面把盘中推算 PE、全收益点位当正式策略输入 | 与回测的收盘信号不一致，刷新可能产生未经收盘确认的目标 | 盘中价格仅展示；正式估值、分位、连续确认全部使用发布的已收盘日线 |
| 买卖点只看全历史 PE 阶梯，其他窗口用“或”连接 | 未满足 ERP 和三窗口共识时也可能提示加减仓 | 用完整规则扫描下一收盘日的条件点位，校验三窗口共同目标；明确假设和每次最多一档 |
| 命令行 `run_model.py`、`today.py` 仍给单窗口目标 | 同一快照页面 HOLD，命令行可能显示37.5% | 统一严格三窗口；`today.py` 明确改为离线诊断，删除把最新国债倒灌旧日的逻辑 |
| JS 配置、Python 配置、阶梯表各自硬编码 | 修改参数后容易静默分叉 | JS 直接读取同一 `hs300/config.json`；阶梯、窗口和版本均从配置产生 |
| 国债20页抓取吞掉单页异常，并无限向后填充 | 历史分位可能受残缺国债数据影响 | 检查分页元数据和内容，残缺则失败；对齐时拒绝超过7日的国债补值，校验数值、排序和重复日期 |
| 失败静默回旧缓存、界面更新时间取本机当前时间 | 用户可能误以为旧数据刚刷新成功 | 返回缓存状态、实际生成时间、失败原因；旧快照暂停交易提示 |
| 前端请求无超时、错误响应处理不足 | 慢接口会持续卡住 | 后端24秒总限时并取消请求；前端35秒限时，所有退出路径恢复按钮，HTTP/JSON/结构异常均可重试 |
| 日线缓存可能覆盖收盘定时刷新 | 15:10仍可能沿用前一日盘中缓存 | 北京时间15:10后，交易周内发现缓存早于当日则强制重抓日线；不纳入15:10前的当日行 |
| 日线历史起点用“当前日期减5800天” | 日后全历史窗口会偷偷变成移动窗口 | 固定请求起点2010-01-01，保留全部可用PE历史 |
| 分位逆映射取整索引偏一位 | 参考阈值与 `<=` 经验分位不完全一致 | 使用 `ceil(p*N)-1`；条件观察线取整后再次用模型复算 |
| 缺少一个窗口也可能宣称共识 | 数据不足时降低门槛 | 只有所有配置窗口均有效才允许共识 |
| CAGR默认净值从1起、交易日年化指数有一日偏差 | 子区间/非1初始净值收益率计算错误 | 使用末值/初值和实际收益区间数量；两端同步修正 |
| 历史记录写入晚于返回payload | 最新一次刷新未出现在当前历史里 | 先保存历史再构造结果，并合并同实例并发刷新 |

## 策略本身：哪些成立，哪些没有被证明

1. 代码实现的规则是：各窗口 `min(PE阶梯, ERP闸门)` 后向下量化到12.5%网格；三个目标完全一致才输出目标；否则 HOLD。正式信号仅用收盘，历史分位排除当日观测。
2. 回测先赚入场持仓对应的当日收益，再按前一交易日已知目标收盘成交；现金与股票分别记账，费用按实际成交额扣。买1日、卖2日确认，单次最多12.5个百分点、5个百分点死区。新增精确成交日期及HOLD中断确认测试。
3. 三个窗口高度重叠，不是三个独立证据。严格一致规则曾在同一样本内比较挑选，历史回报存在参数选择偏差。改变未来数据不影响过去信号，只能排除程序性前视，不能排除历史数据修订、可得时间或样本选择偏差。
4. 国债按日期对齐并不证明其发布时点在当天交易之前可得；本策略下一交易日收盘成交降低这个问题，但当前数据源不是严格的历史时点数据库，无法据此认证完全无数据可得性偏差。
5. 未拿到可核实交易流水、完整独立样本外记录或盲测期。因此不能写“实战打赢”“已经证明未来有效”。未来数据应保留原始版本、日期和参数冻结记录，继续进行不调参的前向观察。
6. 规则分歧表示不调仓，不代表市场必然没有投资优势。HOLD可能在下跌时维持高仓位，这是既定策略取舍，不能包装为风险自动清零。
7. 页面未读取真实持仓。目标100%不等于立即满仓：必须先结合实际资金池仓位、确认日数、死区及单次步长。条件观察线固定盈利和国债，换日、盈利、成分股或利率变化后必须重算。
